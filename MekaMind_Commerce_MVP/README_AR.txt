MekaMind Commerce MVP — الموقع ولوحة الإدارة
=============================================

النسخة الحالية تشمل:
- موقع عربي بهوية MekaMind الأصلية: الشعار المستخرج من المنشور، ألوان الكحلي والسماوي، وصورة الـGateway.
- كتالوج منتجات وخدمات يُقرأ من قاعدة بيانات D1.
- نموذج طلب داخلي لا يحوّل العميل إلى واتساب، مع موافقة واضحة على استخدام بيانات التواصل ومحدد بسيط لمحاولات الإرسال المتكررة.
- حفظ الطلبات في D1 وإعطاء رقم طلب، مع تأكيد للعميل بعد نجاح التسجيل.
- لوحة إدارة محمية عند /admin.html لإضافة المنتجات والخدمات وتعديلها ونشرها أو إخفائها.
- إدارة الطلبات: بحث، قراءة التفاصيل، تحديث الحالة، وإضافة ملاحظات داخلية.
- رابط واتساب مباشر للعميل من لوحة الإدارة لتأكيد السعر والتوفر والتفاصيل يدويًا.
- إشعارات WhatsApp Cloud API اختيارية، عند توفير بيانات Meta وقالب معتمد.

الاستضافة التي بُنيت عليها النسخة
--------------------------------
Cloudflare Pages + Pages Functions + Cloudflare D1. هذا يسمح باستضافة الملفات الثابتة وتشغيل الـBackend وقاعدة البيانات ضمن حساب واحد. اخترناها بدل الاعتماد على Vercel Hobby لأن سياسة Vercel الرسمية تقصر خطة Hobby المجانية على الاستخدام الشخصي وغير التجاري.

النشر عبر GitHub (من دون بناء Frontend)
--------------------------------------
1) أنشئ Repository جديدًا في GitHub باسم mekamind-commerce-mvp.
2) ارفع محتويات المجلد كلها إلى جذر المستودع، خصوصًا: public/ وfunctions/ وschema.sql وpackage.json.
3) سجّل في https://dash.cloudflare.com/.
4) افتح Workers & Pages ثم Create > Pages > Connect to Git، واربط حساب GitHub واختر المستودع.
5) اختر Production branch = main. اترك Build command فارغًا، واجعل Build output directory = public.
6) انشر أول نسخة. قد لا تعمل الطلبات حتى تُنشئ قاعدة البيانات وتربطها في الخطوات التالية.

إنشاء قاعدة البيانات
--------------------
1) من Cloudflare Dashboard افتح Storage & Databases > D1، وأنشئ قاعدة باسم mekamind-db.
2) افتح Console الخاصة بالقاعدة، وانسخ محتوى schema.sql بالكامل والصقه في SQL Console ثم نفّذه مرة واحدة. هذا ينشئ الجداول ويدخل منتج Gateway والخدمات الأولية.
3) افتح مشروع Pages > Settings > Functions > D1 database bindings، وأضف binding:
   Variable name: DB
   D1 database: mekamind-db
4) احفظ الإعدادات وأعد النشر (Redeploy) حتى يعمل الربط.

إعداد بيانات دخول الإدارة
--------------------------
من مشروع Pages افتح Settings > Variables and Secrets، وأضف المتغيرات التالية لبيئة Production:
- ADMIN_USERNAME: اسم مستخدم الإدارة الذي تختاره.
- ADMIN_PASSWORD: كلمة مرور قوية وفريدة، خزّنها كـSecret.
- ADMIN_SESSION_SECRET: قيمة عشوائية طويلة (32 حرفًا أو أكثر)، خزّنها كـSecret.
لا تضع هذه القيم داخل ملفات HTML أو JavaScript ولا ترفعها إلى GitHub.
بعد إعادة النشر افتح:
  https://YOUR-SITE.pages.dev/admin.html
وسجّل الدخول بالاسم وكلمة المرور اللذين ضبطتهما.

إشعارات واتساب للطلبات (اختيارية)
---------------------------------
الطلبات تُحفظ في قاعدة البيانات وتظهر في لوحة الإدارة حتى لو لم تُضبط إشعارات واتساب. لتمرير إشعار تلقائي إلى رقم متابعة عبر WhatsApp Cloud API، يلزم إعداد حساب WhatsApp Business Platform مع قالب رسالة (Utility) معتمد من Meta.
أضف المتغيرات الآتية كـSecrets / Variables في Cloudflare Pages ثم أعد النشر:
- WHATSAPP_ACCESS_TOKEN: Access Token من Meta (Secret).
- WHATSAPP_PHONE_NUMBER_ID: Phone Number ID الخاص برقم الإرسال في Cloud API.
- WHATSAPP_NOTIFY_TO: رقم الشخص الذي يستقبل إشعارات الطلبات مع كود الدولة، أرقام فقط دون +.
- WHATSAPP_SENDER_PHONE_DIGITS: رقم الإرسال بصيغة أرقام فقط، مثل الرقم التجاري 201214330471 إذا كان هو رقم Cloud API. رقم الاستقبال يجب أن يكون مختلفًا عنه.
- WHATSAPP_TEMPLATE_NAME: اسم القالب المعتمد، مثل order_notification.
- WHATSAPP_TEMPLATE_LANGUAGE: كود اللغة المعتمد للقالب كما يظهر في WhatsApp Manager، مثل ar أو ar_EG.
- META_GRAPH_API_VERSION: إصدار Graph API المدعوم في حساب Meta (اختياري؛ افتراضي النسخة الموجودة في الكود).

قالب الرسالة يجب أن يكون Utility ومعتمدًا، مع سبعة متغيرات بالترتيب:
طلب جديد من موقع MekaMind
رقم الطلب: {{1}}
الاسم: {{2}}
رقم العميل: {{3}}
نوع الطلب: {{4}}
المنتج / الخدمة: {{5}}
الكمية: {{6}}
الموعد والتفاصيل: {{7}}
يجب أن يطابق ترتيب ومتغيرات القالب ما يرسله الكود. عند عدم ضبط WhatsApp API، يتابع الفريق الطلبات من لوحة الإدارة مباشرةً ولا يتم إرسال إشعار واتساب تلقائي.

إدارة المنتجات والخدمات
-----------------------
- من /admin.html ادخل إلى المنتجات أو الخدمات.
- رابط سياسة الخصوصية: /privacy.html.
- أضف الاسم والوصف والحالة. اجعل الحالة «منشور» كي تظهر في الموقع.
- المنتج يقبل رابط صورة؛ استخدم مسارًا داخل الموقع مثل /assets/gateway-board.jpg أو رابط صورة HTTPS. رفع الصور من الكمبيوتر مباشرةً غير مفعّل في هذه النسخة.
- اترك نص السعر «اطلب عرض سعر» لو لم تعتمد سعرًا نهائيًا؛ يمكن للعميل إرسال الطلب ثم تتأكد أنت من السعر والتوفر.
- حذف المنتج نهائي من D1. لإخفائه مؤقتًا غيّر الحالة إلى مسودة.

إدارة الطلبات
-------------
- كل طلب يحمل رقمًا مثل MM-261021-XXXXXX.
- حدّث الحالة: جديد، تم التواصل، عرض سعر، تم الاتفاق، قيد التنفيذ، مكتمل، أو ملغي.
- الملاحظات الداخلية لا تظهر للعميل.
- رابط واتساب داخل الطلب يفتح محادثة مع رقم العميل، مع رسالة متابعة جاهزة.
- لا يوجد دفع إلكتروني أو حساب عميل. نموذج الطلب يطلب موافقة العميل على استخدام بيانات التواصل للرد على الطلب.

الاختبار
--------
- بعد النشر، جرّب عرض المنتجات والخدمات من الصفحة الرئيسية.
- أرسل طلبًا تجريبيًا باسمك ورقمك، ثم تأكد أن رقم الطلب يظهر في رسالة نجاح الموقع.
- افتح /admin.html، سجّل الدخول، وتحقق أن الطلب ظاهر ويمكن تغيير حالته.
- لو ظهر خطأ إعداد قاعدة البيانات، راجع وجود D1 binding بالاسم DB وأن schema.sql نُفذ بنجاح.
- إذا نجح حفظ الطلب لكن WhatsApp API غير مفعّل، سيظهر الطلب في لوحة الإدارة مع حالة الإشعار «غير مفعّل»؛ لا يعني ذلك فقدان الطلب.

ملاحظات عن النسخة
-----------------
- الـMVP لا يرسل مدفوعات ولا يؤكد سعرًا نهائيًا أو مخزونًا تلقائيًا.
- إشعارات واتساب لا تعمل دون بيانات Meta وقالب معتمد ورقم متابعة مستقل عن رقم الإرسال.
- لا تشارك كلمة مرور الإدارة أو Access Token مع أي شخص، ولا تضعها في المستودع العام.
- لحدود الخطط المجانية الحالية راجع صفحات Cloudflare Pages / D1 الرسمية؛ الحدود والخطط قد تتغير.
